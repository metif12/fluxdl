Pure V · HTTP(S) · drop-in RPC surface

The transfer manager, not a fork.

fluxdl is the download engine Fluxget needs, written from scratch in V. Same JSON-RPC shape, same session format — so switching engines is a host and port change, and reverting is the same change backwards.

What it actually does

No marketing adjectives below. Each line is something with a test behind it.

Multi-connection HTTP(S)

One file, N byte ranges. Even split, remainder on segment zero — the arithmetic aria2 uses, so the progress bar finishes when it looks finished.

Resume from a prefix

Reads what is on disk and plans only the remainder. An overshooting offset produces an empty plan, never a request for a byte that does not exist.

Honest about Range

A one-byte probe detects a server that ignores Range and collapses to one connection instead of writing N full bodies into one file.

A session file you can trust

aria2's own flat format, written atomically by rename. A corrupt line costs one entry, never the queue — and the loss count is reported.

The RPC surface Fluxget calls

25 methods on loopback JSON-RPC: string-valued numbers, the leading token: argument, system.multicall, and all.

Built by the same v

No C shims, no GPL binary fetched by a script, no second HTTP stack. V's net.http owns the wire; this repo owns the manager.

Where the complexity lives

The manager is pure enough to test without a network. Only one file in the engine opens a socket.

01

Probe

Ask for one byte. Learn the total length and whether ranges are honoured.

02

Plan

Subtract the on-disk prefix. Split the remainder into even, inclusive ranges.

03

Create once

Open the output file before workers start; only shrink it if a stale copy is too long.

04

Fetch

One streaming downloader per range, each writing at its own offset.

05

Account

Each worker owns one result slot; cancellation is checked between segments.

Roadmap

Ordered by what makes the engine usable. A milestone is done only when a test would have caught it being wrong.

Done M0 · manager brain

Byte-range planning, resume, URL/name derivation and the aria2-format session file. Pure, no sockets.

Done M1 · HTTP transfer

Multi-connection HTTP(S), one-byte Range probe, per-download options and the download CLI.

Done M2 · RPC cut-over

The aria2.* subset Fluxget calls, on the same loopback JSON-RPC shape. Reversible by host and port.

Done M3 · hardening

vpm package, cancellation tokens, bounded queue, digit validation and constant-time token checks. Session restore, supervision and the notice queue are still absent.

Done M4 · FTP

Whole-file downloads over net.ftp, behind the same Fetcher seam as HTTP.

Done M5 · BitTorrent

Trackers, DHT, PEX, magnet metadata, rarest-first pieces, SHA1 verification and opt-in seeding.

Done M6 · Metalink, checksums

Metalink 4 files and URLs, plus md5/sha1/sha256 verification of completed downloads.

Quick start

V 0.5.2. v fmt is law. Tests are network-free — 72 of them across six module test files.

PowerShell
# build
git clone https://github.com/metif12/fluxdl.git
cd fluxdl
v build -o fluxdl.exe .

# see the arithmetic before touching the network
./fluxdl.exe plan https://example.com/big.bin 104857600 8

# fetch for real, resuming from what is on disk
./fluxdl.exe download https://example.com/big.bin -x 8 -d D:/Downloads

# serve Fluxget's JSON-RPC surface on loopback
./fluxdl.exe serve --addr 127.0.0.1:9009 --secret change-me

# verify
v test .
