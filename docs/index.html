Pure V · HTTP(S) · drop-in RPC surface

Built fresh. Built for speed.

fluxdl is a download engine written from scratch in V for one purpose: move bytes fast without dragging a legacy stack along. Multi-connection HTTP(S), BitTorrent, FTP/SFTP and Metalink live behind one interface, with the JSON-RPC shape Fluxget already understands.

What it actually does

No marketing adjectives below. Each line is something with a test behind it.

Multi-connection HTTP(S)

One file, N byte ranges. Even split, remainder on segment zero — the arithmetic aria2 uses, so the progress bar finishes when it looks finished.

Resume from a prefix

Reads what is on disk and plans only the remainder. An overshooting offset produces an empty plan, never a request for a byte that does not exist.

Honest about Range

A one-byte probe detects a server that ignores Range and collapses to one connection instead of writing N full bodies into one file.

A session file you can trust

aria2's own flat format, written atomically by rename. A corrupt line costs one entry, never the queue — and the loss count is reported.

The RPC surface Fluxget calls

Loopback JSON-RPC with string-valued numbers, the leading token: argument and system.multicall. Constant-time token checks and notification handling included.

FTP and SFTP

More than HTTP: ftp:// over V's FTP client and sftp:// through an argv-driven external client, both behind the same Fetcher seam.

BitTorrent that verifies its pieces

Bencode and metainfo parsing, HTTP trackers, peer wire protocol, rarest-first selection and SHA1 verification of every piece before it is written.

Peer discovery that goes further

DHT fallback, PEX and magnet metadata exchange. Bare magnets resolve without a tracker, and completed torrents can be seeded to inbound peers.

Metalink and checksums

Metalink 4 files and mirror URLs, plus md5, sha1 and sha256 verification that fails a download on mismatch.

Cancellation and supervision

Pause and remove signal a worker's cancellation token. A stall supervisor restarts stuck downloads; GET /health reports readiness.

Cookies and robots, handled

A locked cookie jar and per-host robots.txt rules, so a server's own preferences are respected before a request goes out.

Built by the same v

No C shims, no GPL binary fetched by a script, no second HTTP stack. Installable as a vpm package; V's net.http owns the wire.

Where the complexity lives

The manager is pure enough to test without a network. Transports sit behind one interface and stay out of the test suite.

01

Probe

Ask for one byte. Learn the total length and whether ranges are honoured.

02

Plan

Subtract the on-disk prefix. Split the remainder into even, inclusive ranges.

03

Create once

Open the output file before workers start; only shrink it if a stale copy is too long.

04

Fetch

One streaming downloader per range, each writing at its own offset.

05

Account

Each worker owns one result slot; cancellation is checked between segments.

Quick start

V 0.5.2. v fmt is law. Tests are network-free — 102 of them across fourteen test files.

PowerShell
# build
git clone https://github.com/metif12/fluxdl.git
cd fluxdl
v build -o fluxdl.exe .

# see the arithmetic before touching the network
./fluxdl.exe plan https://example.com/big.bin 104857600 8

# fetch for real, resuming from what is on disk
./fluxdl.exe download https://example.com/big.bin -x 8 -d D:/Downloads

# serve Fluxget's JSON-RPC surface on loopback
./fluxdl.exe serve --addr 127.0.0.1:9009 --secret change-me

# verify
v test .
